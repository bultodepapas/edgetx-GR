## 2. Architecture understood

```text
GaugeDialPro/main.lua (24 slots) ─┐
                                 ├─> GaugeCore/app.lua
GaugeBarPro/main.lua  (42 slots) ─┘      ├─ shared telemetry/ranges/state/theme
                                        ├─ dial_layout + dial_renderer
                                        └─ bar_layout + bar_style + bar_faces + bar
```

The frontend files own registration, version-gated option definitions, labels,
and the stable wire contract. `app.lua` parses options, resolves sources and
ranges, selects the family renderer, and stages structural rebuilds. Dial Pro
loads 14 chunks; Bar Pro loads 17. Multiple instances of one family share their
module tables. A mixed Dial + Bar screen retains an estimated 866.7 KB because
the two frontend caches are separate.

Important release invariant: widget options are positional persistent data.
Existing keys, types, defaults, and order must not change. Fixes may change
labels/behavior or append new slots, but must not reorder the published
contracts.

## 5. Findings

### F-01 — split-widget documentation exposes the wrong core-ten model (P1)

`DOCS.md` correctly says the split widgets share slots 1–9 and use slot 10 for
`DialStyle`/`BarPreset`, but the immediately following “Core ten” table is the
legacy GaugePro contract. It inserts a generic `Style` choice and shifts
`ColorMode`, `Precision`, and `ShowMinMax`. The appended table then mixes Dial
and Bar fields without publishing the actual 24/42-slot orders.

This directly produces “my option is missing” reports even when the firmware is
correct. Counts elsewhere are also stale: some docs still say 222/206 scenes
and 150 Bar cases, while the current generators report 223/207 and 151.

**Fix:** generate two authoritative option tables directly from the frontend
`DEFS` arrays and embed them in the docs. Keep the legacy table in an explicitly
separate migration appendix. CI must fail when generated docs differ.

### F-02 — responsive/fallback behavior is silent (P1)

`bar_style.resolve()` records downgrade reasons, including:

- `dual-rail-requires-zero-origin`
- `dual-rail-zero-outside-range`
- `zero-origin-clamped`
- `segments-object-budget` / `segments-responsive`
- `blocks-chamfer-to-square`
- `surface-compact`
- Expressive motion reduced to Refined in micro/short zones

Those reasons are exported to development manifests but never reach the pilot.
Therefore an explicit option can appear inert even though the renderer made a
deliberate safety/resource decision.

**Fix:** distinguish inherited Auto adaptation from an explicit override that
cannot be honored. For explicit overrides, expose a short, non-alarming
`LIMIT`/`FALLBACK` information badge after settings update and retain a compact
reason string for diagnostics. Every explicit fallback needs a test proving
either exact rendering or a visible notice.

### F-03 — visual catalog provenance is not trustworthy enough (P1)

Adding `br-minmax-text` shifted every numeric filename after case 89. `run.py
all` wrote the new 090–207 files but did not remove the old numbered files.
Current measured state:

- 380 PNG files in `screenshots/`
- 269 unique filenames referenced by `CATALOG.md`/`INDEX.md`
- **117 unreferenced PNGs**, beginning with the obsolete
  `090_barra_br-tall.png`

`verify_dupes.py` still exits successfully because its classifier recognizes
scene names and themes; it does not reject stale/unreferenced assets. In
addition, `run.py all` refreshed 215 stock/layout images but preserved 48 older
theme captures in the merged run log. `RUN_SUMMARY.md` receives a new generated
timestamp for the combined 263 records without identifying carried-forward
captures.

**Fix:** build the expected filename set after generation, delete only stale
files inside the exact screenshot directory, fail on unreferenced PNGs, stamp
each record with `run_id`, source hash, simulator hash, theme, and capture time,
and label retained sections as carried forward. Prefer `all` to capture all
declared themes or explicitly say “stock + retained theme evidence.”

### F-04 — vertical true-Hex misses the ordinary-frame target (P2)

`dev/instructions.lua` fails on `120x300 vertical true-hex-10` because ordinary
refresh is exactly 2,000 instructions; `dev/measure_frames.lua` independently
reports 2,004. The project gate is strict `<2000`. The firmware limit is 20,000,
and the same scene's worst structural/transition callback is 8,800, so this is
not an imminent radio kill. It is a real performance-regression gate failure
with no margin.

The hot path is `bar.update()` → `bar_faces.updateRenderState()` →
`segmentedUpdate()` → partial/point/whole cell update → `paintCell()` plus the
exact head/history update. The Hex face pays for three retained primitives per
cell.

**Fix:** add counters around those stages, identify dirty cell indices, and
avoid scanning/repainting cells whose fraction, palette, and opacity are
unchanged. Target `<=1800` ordinary instructions to restore margin; do not solve
this by weakening the gate. Preserve the 40-object ceiling, exact partial cell,
and allocation limit.

### F-05 — scalar native telemetry/state path is closed; rich types remain (P2)

The model generator now writes EdgeTX's real nested telemetry-sensor union
(`id1`/`id2`/`cfg`) and persists widget sources as canonical `tele(N)` values.
A Widget-Studio-only simulator seam feeds the firmware's public
`setTelemetryValue()` path, maintains or drops the real telemetry link, and can
change a value after widget creation without rebuilding the model. Production
radio builds are unaffected because every added API/transport entry is guarded
by `SIMU && WIDGET_STUDIO`.

The final run recovers the formerly false or skipped scalar cases:

- `f4-auto-rssi` resolves RSSI/`dB` and the Steps Auto face;
- RxBt retains precision and sensor-aware scale/history;
- T1 proves low-is-good threshold direction;
- NO LINK, NO DATA, and STALE are produced by real firmware link/current/aging
  state, including both chip settings;
- Damping 0 and 9 receive the same live 10→90 transition without recreating
  the widget; their rendered needle geometry differs;
- `Ail`, `CH1` (`ch(0)`), and `Thr` bind native local sources.

Eight cases remain explicitly skipped rather than mislabeled PASS: six CELLS
table/aggregation variants, one timer-typed source, and the descending-history
post-step. These require structured telemetry/timer or additional local-source
orchestration; they are the residual F-05 scope.

### F-06 — fullscreen Bar composition is visually under-resolved (P2)

In the current 800×480 native screenshots, the default fullscreen Bar places
the large value around y=168–233 and the rail around y=418–437, leaving roughly
184 px of empty vertical separation. The Hex fullscreen variant has the same
split. The details layout places `min`/`max` captions at the extreme screen
edges in the smallest font, far from the value they qualify.

Nothing clips and every value is readable, but the screen looks unfinished and
the rail loses its relationship to the number. Dial Pro's fullscreen
composition does not have this problem.

**Fix:** introduce a genuine fullscreen Bar profile. Group value, rail, name,
state, and history into one centered instrument block; use a thicker minimum
rail; cap the value-to-rail gap; and size min/max captions one ramp step above
the current XXS treatment. Validate Continuous and Hex on light/dark themes.

### F-07 — real current-firmware settings dialog is now verified (P2)

`settings_probe.py` drives the actual simulator UI: it selects Gauge Bar Pro,
opens the widget menu, enters Widget settings, captures the first page, then
swipes the real scroll container to its end. The evidence shows the translated
top contract (`Source`, `Scale low/high`, thresholds, direction, colour mode)
and the final Bar rows (`Panel colour` through `Name position`, slot 42) with no
clipping or missing controls:

- [real widget menu](settings/S01-widget-menu.png)
- [first settings page](settings/S02-settings-top.png)
- [last settings page](settings/S03-settings-bottom.png)

The conditional-control usability concern remains architectural: EdgeTX shows
all 42 flat rows and offers no per-option visibility callback. Documentation
now carries the dependency contract, while the visual proof establishes that
the controls do show and the form reaches its last row. A separate 2.11 build
is still needed to capture the intentionally reduced ten-slot view.
